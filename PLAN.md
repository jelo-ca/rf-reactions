## 0. What we're building

A local web app for a **live demo**. The user holds a freshly pulled Riftbound card inside an on-screen guide box. Within ~300ms the app identifies the exact printing, shows its price, and fires a meme-y reaction whose intensity scales with the card's value.

### Goals
- **Accuracy:** ≥ 90% top-1 correct on the eval set (stretch: 95%).
- **Latency:** p95 < 300ms from "card held still" → reaction starts, on the demo laptop.
- **Fun:** six reaction tiers, from a sad "meh" to a full-screen cinematic.
- **Explainable:** a debug panel showing live state, top matches, scores, and timings.

### Non-goals (do NOT build these)
- No cloud services, servers, databases, auth, or deployment.
- No automatic card detection anywhere in the frame — we use a fixed guide box.
- No PWA, offline sync, manifests, or IndexedDB.
- No live price lookups at runtime. Prices are a **one-time snapshot** fetched by the pipeline (Phase 0) and never refreshed automatically.
- No network calls from the app at runtime. Everything the app needs is fetched once, cached, and bundled.
- No vector database. Search is brute-force in a Web Worker.
- No copyrighted meme audio or images. Sounds are synthesized (see Phase 5).

### Core architecture
```
┌──────────── Fetch & cache (Python, run once) ────────────┐
│ card source API → data/raw + images   ·   price API → snapshot │
└──────────────────────────────┬──────────────────────────────┘
                               │ normalized into data/cards + data/prices
┌─────────────── Offline (Python, run once) ───────────────┐
│ card images → augment → embed → embeddings.bin + model.onnx │
└──────────────────────────────┬──────────────────────────────┘
                               │ copied into app/public/
┌─────────────── Browser (all on-device) ──────────────────┐
│ Main thread: camera · guide box · stability check · UI · FX │
│ Vision worker: crop → tensor → ONNX embed → search → match  │
└────────────────────────────────────────────────────────────┘
```

## 3. Data contracts

### 3.1 `data/cards/cards.csv` (generated by `fetch_cards.py`)
```
printing_id,name,set_code,collector_number,rarity,variant,image_file,image_hash,source,source_id,tcgplayer_id
OGN-001,Example Unit,OGN,001,Common,normal,OGN-001.png,9f2c…,riftcodex,abc123,654321
OGN-001F,Example Unit,OGN,001,Common,foil,OGN-001.png,9f2c…,riftcodex,abc123,654321
```
- `printing_id`: unique, filename-safe, derived from the source's card code (e.g. set + collector number + variant suffix).
- `variant`: one of `normal | foil | alt_art | promo`, derived from source metadata (alternate-art, overnumbered, promo flags).
- **Foil rows:** most card sources list one entry per card, not per finish. Create a `foil` row only when the price source reports a separate foil price. Foil rows reuse the normal image and embed identically — expected (see §6.4).
- `source_id` / `tcgplayer_id`: kept so prices can be matched by ID rather than by name.
- `image_hash`: perceptual hash (pHash) of the reference image. Printings with the **same** hash share a picture (typically normal vs. foil). Printings of the same card name with **different** hashes look different (promo, alt art, special layouts such as centered text) and must be told apart visually (§6.4).
- **Printing coverage:** for every card name in the pool, *all* of its printings are included, even ones from sets outside `DEMO_SETS` (promo sets especially). Otherwise a promo can never be recognized and would be silently matched to its base card.

### 3.2 `data/prices/prices.csv` (generated once by `fetch_prices.py`)
```
printing_id,price_usd,price_field,source,as_of,match_method
OGN-001,0.25,marketPrice,tcgcsv,2026-09-25T20:00:00Z,tcgplayer_id
```
- `price_field`: `marketPrice | midPrice | lowPrice | manual`.
- `as_of`: the TCGCSV `last-updated.txt` timestamp at fetch time.
- `match_method`: `tcgplayer_id | set_and_number | name_and_set | manual`.
- Rows in `manual_overrides.csv` (same schema) win over fetched rows.
- Every `printing_id` in `cards.csv` must end up with exactly one row. `ingest.py`/`prices.py` fail loudly otherwise.

### 3.3 App data files (generated) and TypeScript types
```ts

    | "low_score"
    | "low_margin"
    | "same_image_cheapest"  // identical pictures (e.g. foil) → cheaper printing + "could be foil" hint
    | "layout_resolved"      // different pictures, layout check picked one
```

### 3.4 Where embeddings live and how they're searched
- **Built offline** by `embed.py` into `app/public/data/`, served as static files by the dev server. No database, no IndexedDB.
- **Loaded once** by the vision worker at startup into a single `Float32Array`, kept in memory for the whole session.
- **Searched by plain iteration** (exact brute-force dot products, §6.3). At demo scale (~350 printings × 9 rows × 1280 dims ≈ 4M multiply-adds) this takes a few milliseconds. A vector database or approximate index is deliberately **not** used: it only pays off at hundreds of thousands of rows, and exact search has no approximation error.

**`embeddings.bin`:** raw little-endian `float32`, row-major, shape `[rows, dim]`, every row L2-normalized.
**`embedding_ids.json`:** array of length `rows`, where `ids[i]` is the `printingId` for row `i`. Each printing has multiple rows (1 clean + N augmented).
**`layout.bin`:** raw little-endian `float32`, shape `[printings, 80 × 56]` — one normalized edge map per printing, from its clean reference image (§4.7a).
**`layout_ids.json`:** array of `printingId`s, one per `layout.bin` row.

#### Riftcodex (`sources/riftcodex.py`) — default card source
- Unofficial fan project operating under Riot's fan content policy. All read endpoints are public; no key.
- **Cards:** `GET /cards?set_id=<set>&page=<n>&size=100&sort=collector_number`. Paginated response shape: `{ items, total, page, size, pages }`, at most 100 items per page, nested snake_case records.
- **Sets:** `GET /sets` and `GET /sets/set-id/{set_id}` (case-insensitive, e.g. `ogn`). Set records include `tcgplayer_id` (the TCGplayer group ID) and `cardmarket_id`.
- **Card fields to map** (confirm against a real response and the docs' schema reference):
  - `name`, `riftbound_id`, `public_code`, `collector_number`
  - `set.set_id`
  - `classification.rarity`, `classification.type`
  - `media.image_url` (hosted on Riot's CDN)
  - `metadata.alternate_art`, `metadata.overnumbered` → `variant`
  - `tcgplayer_id` → used for price joins
- **Gotchas:**
  - The site's homepage shows an older example path (`/api/cards?limit=`). Trust the docs page (`/cards?size=`), and verify with one request.
  - A **403** is not an auth error — Riftcodex needs no key, so it comes from a gateway/bot filter in front of the API. Log the response body (it contains the only clue), back off, make sure the User-Agent is set, and report to the human instead of retrying in a loop.
- Docs: `https://riftcodex.com/docs/endpoints/cards/`, `/docs/endpoints/sets/`.

#### Riot API (`sources/riot.py`) — upgrade path
- Endpoint group: `riftbound-content-v1`, method `getContent`, which returns all sets with their cards in one call. Locale defaults to `en` (only `en` during beta). Card art fields include `fullURL`, `thumbnailURL`, and `artist`; stats include cost, energy, might, power.
- Requires an **app-specific API key**, obtained by applying through the Riot Developer Portal. The application accepts a working prototype or detailed mock-up, so **this demo itself can be the application.**
- Riot's policy for approved apps: only use Riftbound assets from the Riot API, display official English card text, no monetization without meeting their rules, and no betting or gambling functionality. Our app shows prices and reactions, which is fine, but keep the framing celebratory, not gambling-like.
- Implement this adapter only once the human has a key (`CARD_API_KEY`). Read the endpoint's reference page on the portal for the exact route and response schema before coding.

#### Official gallery JSON (`sources/gallery.py`) — last resort
- Community scripts read the gallery page's underlying data JSON: they extract the Next.js build ID, then request `https://riftbound.leagueoflegends.com/_next/data/{BUILD_ID}/en-us/card-gallery.json`.
- Breaks whenever the site redeploys. Implement only if Riftcodex is unavailable.

### 4.0.3 `fetch_cards.py`
CLI: `python fetch_cards.py [--source riftcodex] [--sets OGN] [--refresh] [--limit 20] [--no-images]`
1. If a cached raw dir exists for this source and `--refresh` isn't set, use the newest one and make **zero network calls**. Otherwise call `fetch_raw()`.
2. `parse()` → filter to `config.DEMO_SETS`.
2a. **Printing coverage** (if `INCLUDE_ALL_PRINTINGS`): collect every card name in the pool, then fetch the other sets (including promo sets, found via `/sets`) and add every printing whose name matches. Log which extra printings were pulled in and from which sets.
3. Download each image to `data/cards/images/<printing_id>.png`. If `data/cards/image_overrides/<printing_id>.png` exists (H7), use it instead of downloading. Skip files that already exist, convert to PNG, verify it opens with Pillow, and warn if the image height is under 600px (low-res references hurt accuracy).
3a. Compute each image's pHash (`imagehash` library) into `image_hash`. Report every card name with more than one distinct hash — these are the look-alike groups (promos, alt arts, special layouts) that the layout check exists for. **Also flag the reverse problem:** a promo whose downloaded image has the *same* hash as its base card means the source reused the base image. List these in `NOTES.md` for the human (H7) — they can't be recognized until a real image is supplied.
4. Write `data/cards/cards.csv` (foil rows are added later by `fetch_prices.py`, only when a separate foil price exists).
5. Print a summary: source, sets, card count, variant breakdown, images downloaded vs skipped.

`--limit` exists so the agent can test the whole path on 20 cards before fetching everything.

### 4.0.4 HTTP etiquette (`http.py`, used by every adapter)
- Custom `User-Agent` of the form `RiftPulls/0.1 (+<config.CONTACT>)`. TCGCSV may block generic or missing User-Agents.
- Sleep at least **100ms between requests** to the same host (TCGCSV's guideline; apply it everywhere). Exceeding TCGCSV's rate threshold gets your IP throttled for 10 minutes.
- Retries with exponential backoff on 429 and 5xx (max 5 attempts), honoring `Retry-After`. Do **not** retry 403s — log the body and stop.
- Every response is saved under `data/raw/` keyed by URL + params, so re-runs hit disk, not the network.
- A request counter printed at the end of every run.

### 4.0.5 `fetch_prices.py` — one-time snapshot from TCGCSV
CLI: `python fetch_prices.py [--force]`

**About TCGCSV:** a free public mirror of TCGplayer's catalog and market prices, rebuilt once a day around 20:00 UTC. Prices are in USD. It has a restrictive CORS policy, so it only works from back-end scripts — which is exactly how we use it. It does not provide per-condition (SKU) prices.

**Endpoints:**
- `GET https://tcgcsv.com/tcgplayer/categories` — find Riftbound's `categoryId` (expected **89**; verify and store in `config.TCGCSV_CATEGORY_ID`).
- `GET https://tcgcsv.com/tcgplayer/{categoryId}/groups` — sets. Match each demo set via the Riftcodex set's `tcgplayer_id` (= `groupId`), falling back to the group `abbreviation`.
- `GET https://tcgcsv.com/tcgplayer/{categoryId}/{groupId}/products` — products (cards and sealed items), with `extendedData` holding `Number` and `Rarity`.
- `GET https://tcgcsv.com/tcgplayer/{categoryId}/{groupId}/prices` — market prices, joined on `productId`.
- `GET https://tcgcsv.com/last-updated.txt` — record this timestamp as the snapshot's `as_of`.

**Budget:** about 3 + 2 × (number of demo sets) requests in total. Set `config.PRICE_MAX_REQUESTS = 20` and abort if the estimate exceeds it.

**Rules:**
- **Frozen by default:** if `data/prices/prices.csv` already exists, exit without fetching unless `--force` is passed. No scheduled refresh.
- **Price rows are keyed by `(productId, subTypeName)`**, not `productId` alone — one product can have several prices (for example normal and foil).
- **Foil handling:** inspect the real `subTypeName` values for Riftbound (likely something like `Normal` and `Foil` — confirm and record them in `NOTES.md`). For each card with a foil price, add a `foil` row to `cards.csv` (same image, `printing_id` + `F`) plus its price row.
- **Which price field:** `marketPrice`. If it's null (low sales volume), fall back to `midPrice`, then `lowPrice`, and record which field was used in a `price_field` column.
- **Skip sealed products:** only keep products whose `extendedData` has a `Number` or `Rarity` entry.
- **Matching cascade**, recorded in `match_method`:
  1. Riftcodex `tcgplayer_id` == TCGCSV `productId`
  2. set + collector number (TCGCSV `extendedData` `Number`)
  3. normalized name + set (TCGCSV `cleanName`; casefold, strip punctuation and extra spaces)
  4. otherwise → `unmatched.csv`
- Merge `manual_overrides.csv` last (overrides win).
- Optional image fallback: TCGCSV `imageUrl` values end in `_200w`; replacing that with `_in_1000x1000` gives a larger image. Use only if a Riftcodex image is missing, and log it.

### 4.3 `model.py` — bake preprocessing into the model
Wrap the backbone so the browser only has to supply RGB floats in `[0, 1]`:
```python
class Embedder(nn.Module):
    def __init__(self):
        super().__init__()
        self.backbone = timm.create_model(BACKBONE, pretrained=True, num_classes=0)
        self.register_buffer("mean", torch.tensor([0.485, 0.456, 0.406]).view(1,3,1,1))
        self.register_buffer("std",  torch.tensor([0.229, 0.224, 0.225]).view(1,3,1,1))
    def forward(self, x):                # x: [N,3,320,224] float32 in [0,1]
        x = (x - self.mean) / self.std
        f = self.backbone(x)
        return torch.nn.functional.normalize(f, dim=1)
```
Normalization and L2 now happen identically in Python and the browser. This removes the most common parity bug.

### 4.4 `augment.py`
For each clean image, produce `AUG_PER_IMAGE` variants simulating a phone/webcam shot of a card held in a guide box:
- Small perspective warp (scale 0.02–0.06) and rotation (±5°)
- Brightness/contrast shifts, color temperature shifts
- Gaussian or motion blur (mild)
- ISO/sensor noise, JPEG compression (quality 50–90)
- **Synthetic glare:** a soft white elliptical highlight at a random position (custom transform, opacity 0.15–0.5)
- Slight padding/crop jitter (±4% of each edge) to mimic imperfect framing

Seed everything with `SEED`. Save a contact sheet of a few examples to `pipeline/out/aug_preview.png` for a quick human sanity check.

### 4.5 Resizing rule (must match the browser)
Every image fed to the model is resized to exactly **224 × 320** with bilinear filtering, **stretching** (no letterbox). The browser does the same by drawing the guide-box crop into a 224×320 canvas.

### 4.6 `export_onnx.py`
- Export `Embedder` to `app/public/models/embedder.onnx`, opset 17, input name `input`, output name `embedding`, static shape `[1,3,320,224]`.
- Keep **fp32**. Do not quantize for the demo: web execution providers don't reliably support quantized conv ops, and ~20MB loading from localhost is fine.
- Verify with `onnxruntime` in Python: ONNX output vs PyTorch output, cosine ≥ 0.999 on 5 images.

### 4.7 `embed.py`
- Embed every clean image and its augmentations with the ONNX model through `onnxruntime` (not PyTorch). This way reference embeddings come from the exact artifact the browser runs.
- Write `embeddings.bin`, `embedding_ids.json`, and `meta.json` to `app/public/data/`.
- Warn if `embeddings.bin` > 25MB, and suggest shrinking the card pool.

### 4.7a `layout.py` — layout signatures for look-alike printings
Some printings share a card name and often the same art but differ in layout (promos with centered text, full-art or showcase frames). A generic embedding can weigh the art heavily and score these nearly the same. The layout signature captures **where text and frame lines sit**, independent of the art's colors.

Algorithm (implement **identically** in `pipeline/layout.py` and `app/src/vision/layout.ts`; both take the same 224×320 RGB image the model sees):
1. Grayscale: `0.299·R + 0.587·G + 0.114·B`, values in [0, 1].
2. Downsample 224×320 → **56×80** by averaging each 4×4 block. (Exact integer box averaging — no resampling library, so Python and the browser produce identical results.)
3. Sobel gradient magnitude (3×3 kernels, edge pixels replicated at borders).
4. Divide the whole map by its mean (+ 1e-6) so lighting and contrast don't matter.
5. Store the 80×56 map flattened, row-major.

Comparison (`layoutScore(a, b)`): split both maps into the **4 × 5 grid** (20 tiles of 14×16 pixels), compute cosine similarity per tile, and return the **mean of the tile scores**. Centered vs. left-aligned text lights up different tiles even when the art is identical.

Output `layout.bin` + `layout_ids.json` (one row per printing, from its clean reference image) and add the `layout` block to `meta.json`. File size is tiny (~350 × 4,480 floats ≈ 6MB; store as float16 later if needed).

### 4.8 `parity.py`
- Pick 5 clean card images, including at least one from a look-alike group if one exists. Resize per §4.5, save them to `app/public/fixtures/parity/` as PNGs, and save their embeddings **and layout signatures** to `expected.json`.

### 4.9 `scripts/build_data.sh`
Runs ingest → export → embed → layout → prices → parity, stopping on the first error. It **never fetches**: it only reads the cached output of Phase 0. If `cards.csv` or `prices.csv` is missing, it tells the human to run the Phase 0 fetch scripts first.

### 5.4 Signals (`stability/signals.ts`) — pure functions, unit tested
- **Presence:** mean absolute difference between the current tiny frame and the *background snapshot*, on a 0–255 scale. On app start, and via a "Capture empty background" button, store the tiny frame of the empty box.
- **Motion:** mean absolute difference between consecutive tiny frames.
- **Sharpness:** variance of a 3×3 Laplacian applied to a larger **112 × 160** grayscale crop, computed only when motion is already low.

### 5.5 State machine (`stability/machine.ts`) — pure, unit tested
```
IDLE ──presence > PRESENT_T──▶ CANDIDATE
CANDIDATE ──motion < MOTION_T for STABLE_FRAMES frames AND sharpness > SHARP_T──▶ RECOGNIZING
CANDIDATE ──presence < PRESENT_T for EMPTY_FRAMES──▶ IDLE
RECOGNIZING ──result accepted──▶ RESOLVED (fire reaction)
RECOGNIZING ──result ask──▶ ASKING (show chooser) ──user picks──▶ RESOLVED (fire reaction)
RECOGNIZING ──result rejected──▶ CANDIDATE (retry, max RETRIES, then COOLDOWN)
RESOLVED ──▶ COOLDOWN
COOLDOWN ──presence < PRESENT_T for EMPTY_FRAMES──▶ IDLE
```
Only one recognition may be in flight at a time.

### 5.6 `config.ts` — initial values (calibrated in Phase 3)
```ts

  MOTION_T: 4,         // mean abs diff between frames
  STABLE_FRAMES: 3,
  SHARP_T: 60,         // Laplacian variance
  EMPTY_FRAMES: 10,
  RETRIES: 2,
  ACCEPT_T: 0.75,      // cosine score
  MARGIN_T: 0.05,      // best minus runner-up (different card names)
} as const;
```

## 6. Phase 3 — Vision worker, recognition, eval

### 6.1 Worker setup (`vision/worker.ts`, exposed with Comlink)
API:
```ts
interface VisionApi {
  init(): Promise<{ backend: "webgpu" | "wasm"; loadMs: number }>;
  recognize(crop: ImageBitmap): Promise<RecognitionResult>;
  embedOnly(img: ImageBitmap): Promise<Float32Array>; // parity + eval tools
}
```
- `init()`: fetch `meta.json`, `embeddings.bin` (into one `Float32Array`), `embedding_ids.json`, `layout.bin`, `layout_ids.json`, and `cards.json` (needed for names and image hashes). Create the ORT session with execution providers `["webgpu", "wasm"]`. Run **one warm-up inference** on zeros. Return which backend was used.
- **ORT pitfalls — check the current `onnxruntime-web` docs before coding:** the WebGPU build may require a different import path, and the `.wasm` files must be served (configure `ort.env.wasm.wasmPaths` or copy them into `public/`). Record what worked in `NOTES.md`.

### 6.2 Crop and tensor
- Main thread: `createImageBitmap(video, sx, sy, sw, sh, { resizeWidth: 224, resizeHeight: 320, resizeQuality: "high" })` using guide-box video coordinates. Transfer the bitmap to the worker (zero-copy).
- Worker: draw onto an `OffscreenCanvas(224, 320)`, `getImageData`, convert RGBA → planar RGB float32 `[1,3,320,224]` in `[0,1]`. No normalization — it's inside the model.

### 6.3 Search (`vision/search.ts`) — pure, unit tested
Exact brute-force search over the in-memory `Float32Array` (see §3.4):
```ts
export function search(data: Float32Array, ids: string[], dim: number,
                       query: Float32Array, k = 5): Match[] {
  const best = new Map<string, number>();
  for (let r = 0, base = 0; r < ids.length; r++, base += dim) {
    let score = 0;
    for (let d = 0; d < dim; d++) score += data[base + d] * query[d];
    const prev = best.get(ids[r]);
    if (prev === undefined || score > prev) best.set(ids[r], score); // best row per printing
  }
  return [...best].map(([printingId, score]) => ({ printingId, score }))
    .sort((a, b) => b.score - a.score).slice(0, k);
}
```
- Rows and query are unit length, so the dot product is cosine similarity.
- Keep the inner loop simple (plain indexed `Float32Array` access, no `reduce`/`map`) so the JIT optimizes it.
- **Budget:** `searchMs` p95 ≤ 20ms. Only if that's exceeded, in order: reduce dimensions with PCA at build time (1280 → 256), then consider baking the matrix into the ONNX graph as a final `MatMul` so scoring runs with inference. Log any change.

### 6.4 Decision rule (`vision/decide.ts`) — pure, unit tested
Two questions, answered separately: **which card is it** (name), then **which printing of that card**.

**Step A — which card (name):**
1. `best` = top printing. `runnerUp` = best-scoring printing with a **different card name**.
2. If `best.score < ACCEPT_T` → reject `low_score`.
3. If `best.score - runnerUp.score < MARGIN_T` → reject `low_margin`.

**Step B — which printing of that card:**
4. `siblings` = every printing with `best`'s name, taken from `cards.json` — **not** just those in the top 5, so a promo that scored slightly low still gets considered.
5. If there's only one sibling → accept (`ok`).
6. Group siblings by `imageHash`.
   - **Same picture group** (e.g. normal vs. foil): they can't be told apart visually. Pick the **cheapest** printing in the group and mark `same_image_cheapest` so the UI shows a "could be foil: $X" hint. In `nexus_night` pack mode, the group's Nexus Night printings are preferred first (§6.4b).
7. If siblings span **different picture groups** (promo, alt art, special layout):
   - Compute `layoutScore` between the live crop's layout signature (§4.7a, computed in the worker from the same 224×320 image) and each group's reference signature. Record `layoutMs`.
   - Combine: `combined = EMBED_W · embeddingScore + LAYOUT_W · layoutScore` (start with 0.5 / 0.5; calibrate in §6.8).
   - If the top group beats the next by ≥ `LAYOUT_MARGIN_T` → pick it (then apply rule 6 inside it), mark `layout_resolved`.
   - Otherwise → status `ask`, reason `layout_ambiguous`, with `askOptions` = the top two groups' representative printings.

Add to `config.ts`: `EMBED_W: 0.5`, `LAYOUT_W: 0.5`, `LAYOUT_MARGIN_T: 0.03` (initial values; calibrated in §6.8).

**Never** pick the cheapest across *different* pictures — that would label a valuable promo as its base card.

### 6.4b Pack mode (human request, 2026-09-25)
Nexus Night promos reuse their base card's picture, so the camera alone can't tell a Nexus Night promo from its booster printing — but the user knows which kind of pack they're opening. A **pack mode** setting (`booster` default | `nexus_night`) resolves it so the shown price is right.

- Every printing carries `pool` (`nexus_night` = untagged OPP printings, else `booster`), set by `ingest.py`.
- **`booster` mode:** printings with `pool = nexus_night` are removed before search results are used — from `top`, `runnerUp` and `siblings` (Nexus Night cards can't come out of a booster).
- **`nexus_night` mode:** all printings stay candidates (a pack may mix contents). Inside a **same-picture** group (rule 6), prefer the Nexus Night printings: pick the cheapest *of those*; only if the group has none, fall back to the cheapest overall. Different-picture groups still go through the layout check (rule 7).
- Reference implementation: `pipeline/packmode.py` (unit tested; used by `eval.py`). The app's `vision/packMode.ts` must match it.
- UI: toggle with `N`, shown as a badge next to the guide box and in the debug panel; remembered in `localStorage` (wrapped in try/catch, default `booster`). Changing the mode never re-fires a reaction for the card already shown.
- Session metrics record the pack mode with each result.
